### Мотивация:
Трейсинг поможет компании:
1. выявить узкие места и медленные части системы
2. облегчит диагностику ошибок
3. сократить время обработки заказов
4. уменьшить количество жалоб клиентов
5. облегчить передачу информации между разработчиками, т.к. запрос фиксируется вместе со всем контекстом

### В первую очередь Трейсингом лучше покрыть следующие системы:
1. MES и MES API - т.к. это самый ответственный компонент от которого зависят все части системы
2. CRM и CRM API - обеспечивает интеграцию с другими системами
3. Messages Queue - ключевой элемент асинхронной обработки заказов
4. MES db - хранит инфу о заказах и об исполнителях. Задержки с нею могут серьёзно отразиться на производительности системы
5. Shop API - обрабатывает счета и обеспечивает контроль жизненного цикла заказа

### Предлагаемое решение
Для реализации Трейсинга предполагается использование следующих технологий:
- Open Telemetry - для сбора метрик
- Jaeger-UI - для визуализации
- Prometheus - для алертинга

### Аспекты безопасности:
1. Ограничение доступа к данным трейсинга. Только авторизованным пользователям а так же добавить ограничения по ролям
2. Добавить шифрование данных трейсинга при передаче между компонентами системы
3. Настроить маскирование данных в Open Telemetry

### Компромиссы
1. Команда не сможет эффективно использовать трейсинг (не позволяет квалификация)
2. Внедрение трейсинга обойдётся слишком дорого
3. Некоторые системы (или все) написаны так плохо, что интеграция библиотек трейсинга может создать проблемы в работе
