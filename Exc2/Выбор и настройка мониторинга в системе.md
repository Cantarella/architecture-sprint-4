### Мотивация:
Добавление мониторинга к имеющейся системе позволит выявить узкие места и 
увеличить производительность.

### Выбор подхода к мониторингу:
Для нашего случая лучше применить комбинацию из подходов. 
Т.к. у нас нет ориентиров на то где возникает проблема: на уровне сервисов (MES, API, CRM) или на уровне инфраструктуры.

+ Можно, для начала, применить методику 4х золотых сигналов. Нам интересны: насыщенность и задержка
+ **Для API**: RED
+ **Для серверов и баз данных:** USE


### Рекомендуемые, для сбора, метрики:

**1. Метрики производительности**
+ можно начать с анализа скорости загрузки интерфейсов MES, прежде всего страницы со списком заказов

**2. Метрики API (RED-подход)**
+ Number of requests (RPS) for CRM API
+ Number of requests (RPS) for MES API
+ Number of requests (RPS) per user for CRM API
+ Number of requests (RPS) per user for MES API
+ Response time (latency) for CRM API
+ Response time (latency) for MES API
+ Number of HTTP 500 for shop API
+ Number of HTTP 500 for CRM API
+ Number of HTTP 500 for MES API
+ Number of HTTP 500 for shop API


**3. Метрики производительности инфраструктуры (USE-подход)**
+ CPU % for CRM API
+ CPU % for MES API
+ Memory Utilisation for CRM API
+ Memory Utilisation for MES API
+ Number of connections for MES db instance

**Метрики для анализа очереди заказов**
+ Number of dead-letter-exchange letters in RabbitMQ
+ Number of message in flight in RabbitMQ
+ Проверить какие заказы в работе
+ Определить среднее время выполнения заказа
+ Сколько заказов просрочено
+ Количество отменённых заказов (из-за просрочек или других проблем с процессами в компании)
+ Количество заказов от физических лиц (B2C) и других компаний (B2B)

### План действий:
1. На основе собранных метрик, выявить узкие места в системе
2. Расшить узкие места, оптимизировать код
3. Подключить Prometheus для сбора метрик и Grafana для визуализации
4. Настроить АРМ - New Relic для мониторинга производительности API и сервисов
5. Создать дашборды для RED, для USE, Для четырех золотых сигналов
6. Настроить уведомления об ошибках, слишком долгой обработке запросов, вероятных просрочках выполнения заказов, ошибках загрузки ресурсов
